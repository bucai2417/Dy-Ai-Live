# 模型骨架与换装实施方案

日期：2026-11-07。状态：第一阶段已落地，使用项目内置的 PySide6 分层骨架；后续仍可替换为画师精修分层或专业运行时。

已落地内容：`assets/avatars/deepy/` 现在包含 14 个父子关节、13 个基础图层和 3 套可替换服装（水手服、柠檬雨衣、星空礼服）。普通挥手、伸懒腰、比心、害羞、舞蹈、摆尾等动作会驱动手臂、头部、发束和尾鳍；墨镜、皇冠、蝴蝶结作为独立配饰保留。设置里的“原始立绘”仍是安全回退模式，骨架素材加载失败也会自动回退。

## 1. 当前模型能做什么

| 位置 | 已有能力 | 限制 |
| --- | --- | --- |
| app/native/scene.py | 加载分层人物，保留原始立绘回退、眼嘴贴片和原生绘制 | 专业网格变形和更细腻的肌肉 / 布料形变仍需后续素材 |
| app/native/actions.py | 17 个普通动作及缓动，动作会映射到骨骼 | 少数整活仍是场景动画，双腿骑车需要专用素材 |
| app/native/costumes.py + assets/avatars/deepy | 皇冠、墨镜、蝴蝶结配饰和三套服装槽位 | 服装当前是可替换刚性图层，仍需美术补齐更多姿势遮挡 |
| app/native/stunts.py | 骑车、蛛丝摆荡、火箭复用分层人物和手部锚点 | 骑车没有独立腿部踩踏 |
| web/assets/whale/rig.js | 网页 SVG 分层程序化形象 | 与原生立绘不是同一套渲染器，不能直接拿 JS 当原生骨架 |
| web/models/haru | 网页 Live2D 示例 | 是另一角色，当前原生 Scene 不加载 .moc3 |

当前 Deepy 立绘为 983 × 1407 的正面鲸尾形态，没有双腿。第一版构建脚本从现有立绘提取头部、头发和鲸尾，重新绘制基础身体、双臂与服装；正式美术仍应精修被遮挡区域，避免大幅转身或抬臂时露缝。

## 2. 技术路线建议

先做「PySide6 原生 2D 分层骨架 + 服装槽位」，第一阶段已实现挥手、伸懒腰、比心、摆尾和三套服装。这样复用了现有的独立绘制线程、音频口型、横竖屏、暂停和视频输出。Qt 的 QTransform 支持图层变换，QPainter 可以在线程内绘制 QImage；一个绘图设备同一时间只能由一个线程绘制 [1][2]。

| 路线 | 在本项目中的适用判断 | 接入工作与边界 |
| --- | --- | --- |
| 原生 2D 分层骨架（首选首阶段） | 现有画风、正面互动、手臂动作、装扮替换 | 实现父子关节变换和关键帧；关节处需补画和遮盖。刚性图片变换不会自动产生柔软网格变形 |
| Spine + 原生运行时 | 动作库持续扩大，需要服装组合和更完整的动画编辑流程时 | 官方有 C++ 运行时和 Skin / Slot / Attachment；仍需 C++ 绑定或独立原生渲染模块、素材加载及绘制适配，不是安装一个 Python 包就完成 [3][4] |
| Live2D Cubism Native | 以脸部、转头和细腻形变为优先目标时的备选 | 需要正式模型、参数映射、Core / Framework 与原生渲染集成。官方 Native SDK 可程序化驱动 Cubism 模型，不需要浏览器，但本项目还未接入 [5] |
| 独立 3D 路线 | 需求明确变成大幅转身、背面、跨视角骑车时再评估 | 另做立体角色、服装和动作资产，超出这一版正面分层改造的范围 |

以上“适用判断”是结合本项目的工程建议，并非官方性能比较。先验证一只手臂和一套替换衣服，再决定是否需要专业运行时；不要在素材尚未分层时同时迁移三套方案。

## 3. 美术交付：先解决缺失的图层

以同一正面中立姿势交付可编辑 PSD 和透明 PNG。画布可继续用当前 983 × 1407 坐标，或由画师统一放大；所有图层必须共用画布、比例和原点。不要把每层分别缩放到“铺满画布”。运行时可裁剪透明边缘，但必须保留裁剪偏移。

| 组 | 至少拆出的内容 | 交付要点 |
| --- | --- | --- |
| 身体 | 颈部、躯干基础层、鲸尾根部、尾身、左右尾鳍 | 衣服移开或手臂抬起后不能出现空洞；基础层使用适合直播展示的完整内搭 |
| 头部 | 脸、左右眼、眉毛、嘴、左右耳鳍、发饰 | 表情和语音口型与身体动作分开控制 |
| 头发 | 后发、左右侧发、刘海；长发分段 | 手抬起后露出的后发需要补画；前后发绘制顺序独立 |
| 双臂 | 左右上臂、前臂、手部 | 肩、肘、腕处留重叠，补齐原图被袖子和头发遮住的部分 |
| 手势 | 张手、握拳、比心、握把或牵绳 | 当前手套造型不能靠简单旋转生成所有手势 |
| 每套服装 | 上衣、左右袖子、领口、裙前片、裙后片、腰饰 | 与基础身体使用相同关节、坐标和边界；袖子随手臂而非躯干运动 |
| 配饰与道具 | 墨镜、皇冠、手持物、自行车把手 / 蛛丝连接点 | 绑定头部或手部锚点，不能继续只靠屏幕固定比例定位 |

每个可动部件需检查隐藏部分，而不仅是将原图“切成几块”。AI 生图可以帮助出服装设计、补画和手势参考，但生成结果仍需逐层检查对齐、角色一致性、透明边缘和遮挡，不等于已经绑好骨架。

建议第一批美术只做：一套完整基础身体、原水手服、一套外形明显不同的新衣服、两种手势。先确认换装后抬手不露缝，再扩展服装数量。当前鲸尾保留；双腿骑车另做形态与动画，不用假造膝关节。

## 4. 建议的骨架和绘制槽位

骨架是父子关节关系；槽位决定某张图片挂在哪个关节、按什么顺序绘制；服装是一组槽位图片的替换集合。先约定角色自身的 left / right，调试界面可额外显示画面左 / 右，避免素材命名反转。

~~~text
root（场景位置 / 缩放 / 整体翻转）
└─ body_root（身体重心）
   ├─ torso
   │  ├─ neck → head
   │  │           ├─ ear_left / ear_right
   │  │           ├─ hair_left_01 → hair_left_02
   │  │           └─ hair_right_01 → hair_right_02
   │  ├─ upper_arm_left → forearm_left → hand_left
   │  └─ upper_arm_right → forearm_right → hand_right
   └─ tail_01 → tail_02 → fin_left / fin_right
~~~

第一版绘制顺序建议：后发 / 后裙 → 后侧手臂 → 尾部和躯干 → 上衣与前裙 → 前侧手臂 → 颈部 / 脸 / 五官 → 刘海 → 头饰和特效。实际顺序由美术校对；挥手越过脸部时需要动作控制局部前后层级，不能全程固定一套遮挡关系。

每个关节记录父节点、初始位置、角度与允许范围。每个槽位记录关节、图片、原点、绘制顺序和可见状态。角度、位移和图片切换分别做关键帧，进出动作设置短过渡，避免弹幕连续触发时“瞬移”。

## 5. 真正换装的数据约定

以下是下一阶段数据结构示意，不是现在可导入的配置，不能直接填写到 data/runtime.json：

~~~json
{
  "schema_version": 1,
  "model_id": "deepy-layered-v1",
  "canvas": [983, 1407],
  "rig_id": "deepy-whale-v1",
  "skin_id": "raincoat",
  "slots": {
    "torso_clothes": "skins/raincoat/torso.png",
    "sleeve_left": "skins/raincoat/sleeve-left.png",
    "sleeve_right": "skins/raincoat/sleeve-right.png",
    "skirt_front": "skins/raincoat/skirt-front.png",
    "skirt_back": "skins/raincoat/skirt-back.png"
  },
  "hide_slots": ["sailor_collar", "sailor_tie"],
  "compatible_actions": ["idle", "wave", "bow", "tail_sway"]
}
~~~

加载时检查 rig_id、必需槽位、图片尺寸、路径是否仍在模型目录和动作兼容声明。先完整加载新服装，再一次性切换所有槽位；任一文件缺失就保留原服装并提示原因，避免直播中出现半身衣服。删除旧衣专属领口、领带不能只靠覆盖新图遮住。

配饰和服装保存为独立状态：收到墨镜礼物只改变眼镜槽位，不能把已穿的新衣服复原。以后可以扩展帽子、眼镜、手持物组合，服装切换应保留当前口型、音乐进度和动作时间。

## 6. 在现有代码中怎么接入

已新增 app/native/avatar/rig.py，集中处理模型校验、关节变换、过渡与绘制；app/wardrobe.py 负责独立服装与配饰的持久化。素材已放到 assets/avatars/deepy/，web/assets/whale/art 保留原图与眼嘴贴片供回退和口型复用。下表是未来规模增大后可进一步拆分的模块建议，不是当前文件列表。

| 建议模块 | 职责 | 现有接入位置 |
| --- | --- | --- |
| loader.py | 模型包、关节层级、槽位、服装校验；后台预加载图片 | Scene 初始化和更换模型时调用 |
| rig.py | 父子关节变换、锚点、姿势计算；先做刚性图层 | 替换 Scene 内人物部分的整图变换 |
| animation.py | 动作关键帧、过渡、优先级和暂停时钟 | 接收 StageState 的 reaction、mouth、paused 等快照 |
| wardrobe.py | 完整服装预加载、原子切换、配饰独立组合 | 从当前 costume 字段迁移，兼容 original / cool / crown / festival |
| painter.py | 将人物绘到现有 QImage，使用已有布局范围 | 普通场景和 stunts 共用人物实例，避免整活动画仍画旧裁片 |

绘制接口可约定为 draw(painter, state, bounds, elapsed)，返回人物边界与头、手锚点给道具和特效使用；不在每帧创建图片、读文件或请求网络。不要让脑内意图识别直接操纵 Qt 对象，仍通过现有消息和状态快照传递动作 ID。

现有 app/native/actions.py、app/native/state.py、app/brain/intent.py、app/settings_store.py、app/native/preferences.py 和动作相关测试需同步适配。模型声明 capabilities；没有相应关节或手势时，界面提示不可用，避免显示“比心成功”但人物没有手势变化。

原图片渲染器保留为回退：缺少新模型、初始化失败或关闭骨架模式时继续直播，日志说明原因。新模型不应影响音乐、语音回执、礼物排行和奶蛙视频。

## 7. 动作编排与后续互动

动作分通道，避免所有输入互相覆盖：

- 基础层：呼吸、轻摆尾、眨眼持续循环。
- 语音层：现有音频口型单独驱动嘴部；普通挥手不关闭口型。
- 上身层：挥手、指向当前歌曲、双手比心、抱头害羞、摸鱼伸懒腰。
- 全身层：鞠躬、倒立、摆荡、飞行；使用整活场景提供的锚点。
- 附加层：头发与尾鳍小幅跟随，服装和配饰跟随同一骨架。

建议优先级为「人工控制 / 正在播放的整活 → 礼物回应 → 普通弹幕 → 冷场动作」。全身动作占用身体通道，上身动作仍允许口型与眼睛更新。相同文本的独立弹幕仍记录和反馈；忙时按有限队列与过期策略处理，不能用相同文本去重来吞掉触发。

暂停使用统一的逻辑时间：暂停后骨架、物理跟随、道具锚点和音频一起冻结；恢复不能补跑暂停期间积累的时间。冷场候选只在人物空闲且没有语音、点歌或整活竞争时执行，沿用现有调度条件。

| 阶段 | 可以增加的互动 | 依赖 |
| --- | --- | --- |
| 第一批 | 真挥手、点头谢礼、左右尾鳍摆动、瞄一眼新弹幕、冷场伸懒腰 | 基础分层、手臂和头尾骨架 |
| 第二批 | 双手比心、害羞捂脸、指向当前歌曲、抓住飘过的头像气泡 | 手势图片、双臂协调、人物锚点 |
| 第三批 | 手抓蛛丝摆荡、倒立时头发下垂、骑车握把 | 道具锚点、全身姿势与遮挡校对；双腿踩踏另需腿部形态 |
| 服装联动 | 礼物触发穿雨衣 / 节日服，保持已有墨镜 | 两套可替换服装、服装与配饰状态分离 |

## 8. 已实现的使用方式

- 设置 → 人物与互动：选择“分层骨架（可抬手 / 换衣）”、服装和配饰；“显示骨架辅助线”只建议调试时开启。
- 直播控制面板的装扮下拉框同时列出服装和配饰；自然语言支持“穿上雨衣”“穿上星空礼服”“换衣服”“摆尾巴”。
- 送出墨镜礼物仍只切换墨镜配饰，当前衣服不被覆盖；服装切换也不会清除墨镜。
- 暂停时骨架、发束、尾鳍和当前动作冻结，恢复后从暂停位置继续。
- 旧模式可在设置中切换为“原始立绘”；模型文件损坏、缺图或版本不匹配时，画面自动使用原始立绘并提示回退。
- 运行 `python tools/build_avatar.py` 可从现有基础素材重建 `assets/avatars/deepy/`；该脚本不是美术分层工具，精细服装仍应替换对应 PNG。

## 9. 实施与验收顺序

1. 素材小样：只拆一侧手臂、躯干和袖子，做 0° / 45° / 90° 角度预览。确认肩肘不露空、袖子对齐，再批量拆图。
2. 最小骨架：接入原生 Scene，完成 idle / wave / bow / tail_sway，保留现有图片模式回退。调试时能显示骨架线和锚点，但默认直播画面隐藏。
3. 真换装：交付两套轮廓明显不同的衣服；动作播放中切换，旧领口和裙片完全移除，袖子随臂运动，墨镜不丢失。
4. 完善动作：加入手势、脸部独立通道、进出动作过渡、礼物优先级，再迁移骑车和蛛丝道具锚点。
5. 性能验收：在同一台设备分别测试 720×1280 / 1280×720，人物动作、10 个头像气泡、音乐和视频同时运行；记录平均帧率、p95 绘制耗时、内存及 30 分钟稳定性。最小化后仍持续输出，目标 30 FPS 渲染、25 FPS 视频，不用未经测量的“零卡顿”作为结论。
6. 回归验收：暂停 / 恢复不跳姿势，断线重连不重置服装，中文模型名能保存与恢复，缺图回退可用；原有测试和 tools/check_native.py 全部通过。

第一阶段完成标准是“同一角色真的抬手，而且切换上衣、袖子和裙摆后仍能正常抬手”。增加更多整图旋转动作不算完成骨架或换装。
