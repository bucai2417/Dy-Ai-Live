# Dy-Ai-Live 用户使用教程

适用于 Windows 原生桌面版「大肥鱼 / 深蓝 Deepy」。本教程按 2026-11-08 的 main 分支功能编写；旧的 v1.0.0 标签是最初的源码版本，菜单、打包方式可能不同。请以自己下载版本的界面和随包说明为准。

本项目用 Python + PySide6 绘制直播画面，支持弹幕互动、音乐、礼物演出、场景移动和协力钓鱼。你不需要用浏览器展示直播画面，也不需要在浏览器中打开管理后台。

> 使用范围：项目采用 PolyForm Noncommercial 1.0.0，是非商业用途的源码可见项目。公开许可不包含以营利为目的的礼物直播、带货、广告、付费托管或软件销售等使用；如需商业使用，应先取得另行书面授权。完整条款以 LICENSE 为准，第三方组件仍遵循各自许可。详见仓库中的「非商业使用许可说明」。

## 1. 下载哪一版

项目地址：<https://github.com/bucai2417/Dy-Ai-Live>。

| 你的情况 | 选择 | 是否需要安装 Python |
| --- | --- | --- |
| 只想运行程序 | Windows x64 EXE 免安装包 | 不需要 |
| 想修改代码或自行调试 | main 分支源码 | 需要，已验证的构建环境为 Python 3.10 x64 |
| 想查看最初发布的源码 | v1.0.0 Release | 需要；这个版本的源码 ZIP 不是 EXE |

### 1.1 下载 Windows EXE

1. 进入仓库的 **Actions**，选择 Windows 构建工作流。
2. 打开一个 main 分支的成功运行记录，在 **Artifacts** 下载名称带有 `windows-x64` 的产物；不要下载 test-reports，它是测试报告。
3. Actions 下载通常需要登录 GitHub。产物有保存期限；过期时使用较新的成功构建，或由仓库维护者重新运行工作流。
4. 解压下载的文件。如果里面还有一个 `Dy-Ai-Live-版本号-windows-x64.zip`，继续解压这个内部 ZIP，直到看到 `Dy-Ai-Live.exe` 和 `_internal` 文件夹。
5. 将整个程序目录放到自己有写入权限的地方，例如 `D:\Dy-Ai-Live`，然后双击 EXE。

main 的包名会带提交号，例如 `1.0.0+abcdef0`，用于区分同版本号下不同构建。若以后 Release 已有 Windows ZIP 附件，也可直接下载该附件；不要把 GitHub 自动提供的「Source code」当作 EXE。

这是免安装目录包，不是单文件程序。必须保留 EXE 旁的 `_internal`；请先完整解压，不能在压缩包预览中直接运行，也不能只把 EXE 单独移到桌面。可以为 EXE 创建桌面快捷方式。

可选校验：构建产物附带 `.sha256` 文件，在 PowerShell 对内部 Windows ZIP 执行以下命令，将结果与校验文件比较：

~~~powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\Dy-Ai-Live-版本号-windows-x64.zip'
~~~

程序目前未提供数字签名。下载来源和校验值不一致时重新核对文件；不要通过关闭系统防护来解决缺文件或启动问题。

### 1.2 从源码启动

从仓库下载 main 源码并完整解压，或使用 Git 克隆。在包含 `requirements-desktop.txt` 的项目根目录打开 PowerShell。建议使用独立虚拟环境，避免影响其他 Python 项目：

~~~powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONIOENCODING = 'utf-8'
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
.\.venv\Scripts\python.exe -m app --desktop
~~~

如果系统没有 `py` 命令，将第一条建环境命令中的 `py -3.10` 替换为已安装 Python 3.10 的可执行文件路径。此流程直接使用虚拟环境的 Python，不需要先激活环境。

已有 `.env` 时不要覆盖。源码中的 `启动.bat`、`直播画面.bat` 也可启动工作台；若 BAT 使用的 Python 与虚拟环境不同，优先使用上面的明确路径。`自检.bat` 是开发检查入口，普通用户运行程序不需要它。

### 1.3 需要另外准备的内容

- 真实弹幕：可主动推送消息的外部弹幕助手，或其他受支持的采集方式。
- 在线 AI：服务商提供的兼容聊天接口地址、模型名和 API 密钥；没有配置时仍可使用明确指令和内置话术。
- 在线语音：默认 Edge 语音需要联网；也可选择「仅显示字幕」。
- 音乐和互动视频：自行准备有权使用的文件，公开安装包不附带私人歌曲、BGM 或奶蛙视频。
- 透明互动视频解码：EXE 包需另外配置 FFmpeg，具体见第 7 节；仅运行基本画面和原生音频不需要先配置它。

## 2. 第一次启动：先跑通画面

建议先用测试弹幕检查效果，成功后再接真实直播间。

1. 启动工作台，等待右侧状态从连接中变为可操作，确认人物和场景出现。
2. 打开右侧 **接入设置**，选择「模拟弹幕」，勾选「启用弹幕接入」，点击「保存并生效」。如果不想自动生成模拟事件，可关闭接入，直接使用第 4 步的手动测试。
3. 点击预览上方的「横屏 / 竖屏」，选好自己需要的方向。
4. 在 **直播控制 → 互动测试** 输入「挥手」，点击「发送弹幕」；再测试「换衣服」「去钓鱼」。
5. 在 **人工播报** 输入一句中文，点击「立即播报」。若只见字幕没有声音，按第 4、14 节检查语音和静音设置。
6. 点击「测试点赞 +10」或「预览整活」观察动作。测试事件会影响本程序的今日计数，不是平台真实互动记录。
7. 完成后接入真实弹幕，配置 OBS，先做一次本地录制检查声音和画面。

也可以在程序目录的 PowerShell 中使用演示参数：

~~~powershell
.\Dy-Ai-Live.exe --demo
~~~

源码对应命令为：

~~~powershell
.\.venv\Scripts\python.exe -m app --desktop --demo
~~~

**演示只替换弹幕源，不代表完全离线。** 如果配置过在线 AI 或在线语音，仍可能调用这些服务并产生相应请求。已有后台运行时会复用它，完整切换演示环境前先退出原工作台。

<a id="03"></a>
## 3. 认识工作台

左侧是直播预览；右侧是操作区，操作面板不会出现在 MJPEG 直播输出中。

| 入口 | 主要用途 |
| --- | --- |
| 直播控制 | 人工播报、静音、点歌、播放/下一首、人物动作、换装、视频、点赞和弹幕测试 |
| 场景导演 | 选择场景、天气、镜头和移动位置；钓鱼、协力拉钩、跳水、常驻钓台；查看 AI 所知的人物状态 |
| 接入设置 | 直播间名称、弹幕来源、房间号/链接、接入开关；打开「人设 / AI / 语音 / 画面设置」 |
| 画面输出 | 复制 OBS 视频地址、打开纯净画面窗口、保存截图 |
| 预览上方的横屏/竖屏 | 切换布局，并记住上次选择 |
| 暂停直播 | 显示休息画面，停止 AI 回复与语音，暂停音乐并冻结相关玩法进度 |

以下教程中的「直播设置」统一指：**接入设置 → 人设 / AI / 语音 / 画面设置** 打开的对话框。修改后点击底部「保存并生效」，取消不会保存编辑内容。

- `Ctrl+P`：暂停 / 恢复本程序的直播互动。
- `F11`：切换工作台全屏。
- 「跳过当前」：跳过当前播报；音乐切歌使用播放器的「下一首」。
- 「静音输出」：包括 OBS 从本程序捕获的声音，不能当作“只让我自己听不见”的监听开关。
- 「清空本场弹幕和歌单」：清理当前会话内容，不清掉今日累计统计。

**暂停本程序不会停止 OBS 推流，也不会替你关闭平台直播间。** 暂停会取消在途回复并清理待处理内容；不要期待恢复后重放所有暂停期间的消息。结束直播仍需在 OBS 和平台端完成相应操作。

## 4. 配置 AI、语音和内置话术

### 4.1 人设与 AI

打开 **直播设置 → 人设与 AI**：

| 字段 | 怎么填 |
| --- | --- |
| 主播名字 | 人物称呼，例如「深蓝」 |
| 性格风格 | 描述说话方式，例如「幽默温和，简短回答，喜欢鱼类冷笑话」 |
| 回复规则 | 写清不想聊的内容、句子长度、互动提示频率等 |
| 模型接口地址 | 服务商提供的 OpenAI 兼容聊天接口 Base URL；不要填控制台网页或随意拼接完整请求路径 |
| 模型名称 | 该接口实际支持的模型 ID，按服务商给出的名称填写 |
| API 密钥 | 对应服务的密钥；界面留空表示保留已有密钥或使用 .env 配置，不表示清除 |

保存后用「你好，你会什么」测试，再尝试「能不能给大家鞠个躬」。观察实际动作、字幕和日志，不能只凭 AI 口头回答“好的”判断执行成功。

程序会把当前能力、场景、睡眠/驾驶状态、动作和钓鱼状态提供给 AI。AI 识别到受支持的意图后，由程序执行相应操作，仍受功能开关、权限、间隔和队列限制约束。修改人设不会增加未实现的动作或解除常驻钓鱼切换权限。

没有配置模型，或者模型超时、鉴权失败、返回格式不符合要求时，会回退到本地明确指令及允许的内置回复。支持自然语言的模型通常能理解更多表达，但效果取决于模型和接口；遇到不确定情况先用第 12 节的明确命令。

### 4.2 语音与节奏

打开 **直播设置 → 语音与节奏**：

- 「语音引擎」选 **Edge 在线语音**，需要联网；选 **仅显示字幕** 则不合成语音。
- 默认音色标识为 `zh-CN-XiaoyiNeural`，语速示例为 `+8%`，音量示例为 `+0%`。使用引擎支持的音色标识，不要填自己给音色起的昵称。
- 「最小回复间隔」控制播报节奏；「冷场等待」控制主动聊天的等待时间。
- 「模型回复目标字数」是控制模型回复长度的目标，程序尽量按完整句收尾；调得过小会影响内容丰富程度。
- 「优先使用 AI 即兴台词」开启时，欢迎、感谢和冷场话术可能由模型生成。希望稳定使用自己写的句子时，关闭它并启用相应的预设话术开关。
- 「模型不可用时使用内置话术」和「朗读内置话术」分别控制离线回复与其朗读；“离线话术”只表示不依赖聊天模型，Edge 语音本身仍要联网。

使用「人工播报」测试完整句子；播报中点击跳过、发起新的人工播报、暂停直播或预览其他话术，会中断当前发言。排查“读不完整”时先确认没有同时进行这些操作。

### 4.3 修改内置话术

1. 打开 **直播设置 → 内置话术**，在类别下拉框选择欢迎、礼物、冷场、钓鱼、梦话等对应类别。
2. 每行写一条候选句子，不要用换行把同一句拆成数条候选。
3. 只使用页面显示的占位符，例如某些类别支持 `{name}`、`{gift}`、`{count}`；不同类别可用参数不同，以当前提示为准。
4. 检查下方预览。光标放在目标行，点击「播报光标所在话术」试听。
5. 点击「保存并生效」。想撤回某一类修改，可用「恢复本类默认」后保存。

普通话术类别留空会使用默认句子；要关闭播报，请用对应开关。类别中若选择了「规则台词」，编辑区按整段处理，留空表示只做动作。

**话术试听会进入实际直播音频，并停止当前发言。** 建议在未推流时试听；只需检查字幕时可以先静音。

### 4.4 冷场、玩法邀请和梦话

在 **冷场互动** 中分别控制「无人互动时自动做动作」「主动邀请观众体验已开启的玩法」「睡着后说梦话」。

- 冷场动作可依次轮换或随机选择，并可勾选允许出现的动作。
- 邀请会参考已开启玩法，比如提示观众发送“钓鱼”；它只发出邀请，不会因为说了这句话就自动开局。
- 默认可在睡着后约 45 秒触发梦话。想测试长时间睡眠，请发送「去沙发睡觉」，而不是短暂的「打个盹」。
- 正在播报、等待回复、进行特定玩法或暂停时，自动互动可能推迟，间隔不是严格定时提醒。
- 如不希望歌曲中被主动聊天打断，关闭「音乐播放期间也允许冷场聊天」。

## 5. 接入真实弹幕

先在 **接入设置** 选择来源、填写需要的房间信息、启用接入并保存。画面连接正常只表示工作台连上了后台，不代表已经收到平台弹幕；需要让一个真实观众发送测试消息确认。

| 来源 | 适用情况 | 额外要求 |
| --- | --- | --- |
| 模拟弹幕 | 本地演示和功能熟悉 | 不连接真实直播间 |
| 外部助手桥接 | 已有能推送 JSON 消息的弹幕助手；希望不使用浏览器采集 | 助手必须支持主动连接 WebSocket 或 HTTP 回调 |
| 抖音浏览器采集 | 通过本机 Chrome / Edge 读取房间消息 | 可能需要人工登录或完成验证，会启动采集浏览器 |
| 抖音直连 | 已配齐签名环境的进阶用户 | Node.js、兼容且合法取得的外部签名组件，公开包未附带 SDK |

原生画面与弹幕采集互相独立。如果不希望任何浏览器窗口出现，使用 **桥接**；仅演示时可用 **模拟弹幕**。直连缺少签名组件时会回退到浏览器采集，不能把它当作“无条件不开浏览器”的选项。

### 5.1 推荐方式：WebSocket 桥接

1. 工作台选择「外部助手桥接」，启用并保存。
2. 启动你的弹幕助手，按助手自己的说明连接直播间。
3. 在助手的主动推送 / WebSocket 客户端配置中，填写：

~~~text
ws://127.0.0.1:5001
~~~

4. 让助手向该地址推送 JSON 消息，测试弹幕、礼物和点赞是否进入工作台。

这里本项目是 WebSocket **服务端**。如果助手只提供“WebSocket 服务端地址”等待别人连接，并不能直接填上这个地址完成对接，需要助手的客户端推送功能或另写适配转发。

默认监听本机，5001 是桥接端口，8848 是主服务端口，18849 是视频输出端口，三者不要填反。自定义桥接端口可在运行目录的 .env 设置 `BRIDGE_PORT` 并重启。多个来源同时推送同一事件可能重复计数，应只保留实际使用的一条接入链路。

以下是助手开发者可参考的最小消息格式；普通用户通常只需配置助手，不必手工发送 JSON：

~~~json
{"type":"chat","userId":"viewer-001","nickname":"小明","content":"去钓鱼"}
{"type":"like","userId":"viewer-001","nickname":"小明","count":10}
{"type":"gift","userId":"viewer-001","nickname":"小明","giftName":"鲜花","giftCount":1,"giftValue":1}
~~~

每一行是一条独立消息，也支持一个 JSON 数组。建议提供稳定 `userId` 和有效 `avatarUrl`；没有头像时使用昵称首字替代。礼物的 `giftValue` 按**单件价值**传入，程序会乘以 `giftCount`，不要把总价再次当单价。价值用于本项目排行，不应解释为实际人民币收入。

若采集工具能取得可信管理员身份，可通过 `isAdmin: true` 等支持的字段传递。只有全场点赞总量而没有用户身份时，程序可以计算匿名合力，但无法推断是谁点的赞。

### 5.2 助手只支持 HTTP 回调

完整后台也提供消息转发通道。**源码用户**可以另外启动可选 HTTP 桥接：

~~~powershell
.\.venv\Scripts\python.exe -m app.bridge_server --port 5002
~~~

助手将 JSON POST 到：

~~~text
http://127.0.0.1:5002/danmu
~~~

HTTP 服务再经主服务的 `/ws-feed` 转发事件，因此先启动主程序。端口 5002 是这个可选辅助服务的默认端口，不是上一节的 5001。EXE 没有单独的 HTTP 桥接启动开关；只用 EXE 的用户优先选择能主动推送 WebSocket 的助手。

源码自测可在另一个 PowerShell 窗口执行，使用 UTF-8 字节避免中文乱码：

~~~powershell
$payload = @{ type = 'chat'; userId = 'demo-user'; nickname = '测试观众'; content = '挥手' } | ConvertTo-Json -Compress
$bodyBytes = [System.Text.Encoding]::UTF8.GetBytes($payload)
Invoke-RestMethod -Uri 'http://127.0.0.1:5002/danmu' -Method Post -ContentType 'application/json; charset=utf-8' -Body $bodyBytes
~~~

### 5.3 浏览器采集与直连

浏览器采集：选择「抖音浏览器采集」，填直播间房间号或完整链接，保存后按采集窗口提示完成必要登录。这个浏览器只收集弹幕，OBS 仍使用原生输出；关闭采集浏览器可能导致真实消息中断。

直连：公开包仅提供签名接口代码，不附带 `webmssdk.js`。需要自备兼容组件、Node.js，并按 `tools/douyin_sig/README.md` 配置。首次使用不建议从直连排查起步，先用模拟验证程序、再用桥接验证真实事件。

### 5.4 重复弹幕为什么有时没有动作

观众重新发送相同文字会重新处理，不按文字内容一律去重。但同一采集消息的重传、队列上限、歌曲个人占位、场景操作间隔、权限不足、否定表达和直播暂停仍会影响执行。连续发送“不要跳舞”不应触发跳舞。判断问题时同时检查实际消息是否进入、当前状态及工作台提示。

## 6. 把画面和声音接入 OBS

### 6.1 推荐：使用持续视频源

1. 保持工作台运行，在 **画面输出** 点击「复制视频源地址」。默认地址为：

~~~text
http://127.0.0.1:18849/live.mjpeg
~~~

2. 在 OBS 的「来源」中添加 **媒体源**，取消「本地文件」。
3. 把地址粘贴到输入框；如界面提供「输入格式」，填写 `mpjpeg`。
4. 关闭「源不可见时关闭文件」，避免切换场景时中断读取。
5. 设置 OBS 画布与程序方向一致，再将来源适配到画布。

程序常用竖屏尺寸为 720 × 1280，横屏为 1280 × 720。以 **画面输出** 显示的实际尺寸为准；切换方向后 OBS 也需要调整画布比例和来源尺寸，视频地址保持不变。

工作台目标渲染帧率为 30 FPS，MJPEG 输出固定 25 FPS。最小化工作台时独立绘制线程仍持续输出，但实际流畅度受机器性能、编码负载、媒体解码和 OBS 设置影响。程序必须继续运行，电脑休眠、退出程序或后台异常后不会继续输出。

### 6.2 声音单独采集

**MJPEG 地址只包含画面，没有声音。**

- 若 OBS 提供「应用程序音频捕获」，选择实际发声的 Dy-Ai-Live 工作台进程/窗口，减少其他软件声音进入直播。
- 也可以采集桌面音频，确认监听的是程序当前使用的音频设备。
- 同一份声音不要同时通过应用采集和桌面采集进入 OBS，否则会重音或回声。
- 本程序的「静音输出」会让采集到的声音也静音。

先在「人工播报」输入一句话，再播放一段本地音乐；观察 OBS 音量表并录制十几秒回看。确认能同时听到人声和音乐后再使用正式推流。

### 6.3 备选：纯净画面窗口

点击 **画面输出 → 打开纯净画面窗口**，用 OBS「窗口采集」选择该窗口。不要误选带控制面板的工作台。持续视频源更适合后台使用；窗口采集的遮挡、最小化表现由 OBS、系统及采集方式决定，需要在自己的机器上验证。

### 6.4 卡顿时按顺序调整

1. 先分清是人物画面卡、OBS 丢帧，还是联网语音/歌曲等待加载；它们不是同一问题。
2. 使用默认 720 × 1280 或 1280 × 720，不要一开始就提高分辨率。
3. 关闭不需要的纯净窗口、粒子效果、过多气泡或互动视频，观察负载是否下降。
4. BGM 和点歌先用本地文件排除网络等待；透明视频应使用短片。
5. 将 OBS 视频设置与实际来源匹配，检查 OBS 的统计窗口及系统 CPU/GPU 占用。

需要指定尺寸时，退出原程序后在程序目录启动，例如：

~~~powershell
.\Dy-Ai-Live.exe --width 1280 --height 720 --fps 30
~~~

源码对应：

~~~powershell
.\.venv\Scripts\python.exe -m app --desktop --width 1280 --height 720 --fps 30
~~~

## 7. 音乐、背景 BGM 与互动视频

### 7.1 点歌和播放器

在 **直播控制 → 点歌 / 播放列表** 输入歌名，点击「点歌」或按回车。直播画面可显示当前歌曲、进度和下一首；在 **直播设置 → 音乐与画面** 启用音乐、自动播放队列及「直播画面显示音乐播放器」。

观众可发送「点歌 晴天」「播放晴天」「能放周杰伦的晴天吗」，也可发送「下一首」「暂停音乐」「继续播放」「在放什么」。明确指令由本地规则识别，更灵活说法可交给已配置的 AI。

- 「自动播放队列」与「AI 自动点歌」是两回事：前者播放已经加入队列的歌；后者允许 AI 从你确认的歌单中主动选歌。
- 待播队列有容量限制，默认最多 30 首、每位观众最多占用 3 首。达到限制时需要等待或切歌。
- 查到歌名不等于音频一定可播放，网络源可能失效、不可用或只返回试听。优先准备自己的本地曲库。
- 本项目播放歌曲音频，不会自动生成角色演唱或实时 AI 翻唱。

### 7.2 本地曲库

在运行目录创建 `music` 文件夹，将有权使用的音频放进去。支持的扩展名包括 MP3、M4A、AAC、OGG、OGA、WAV、FLAC、WebM、Opus；实际能否播放还取决于文件编码和播放器支持情况。

建议命名为：

~~~text
music/
  歌手 - 歌名.mp3
  自制背景曲.wav
~~~

使用歌名点播，不要把完整文件路径或下载链接当作点歌请求。也可在 .env 用 `MUSIC_DIR` 指定其他曲库目录，重启后使用。公开包不会自带你的歌曲。

### 7.3 限制歌曲与 AI 自动点歌

打开 **直播设置 → 歌曲限制**：

1. 在「额外禁播歌名 / 关键词」填写不希望播放的歌名、别名、歌手等，逗号或换行分隔。
2. 需要自动点歌时，启用「AI 自动点歌（仅限确认歌单）」。
3. 将已经核对并试听的歌曲写入「已确认自动点歌歌单」，每行格式为 `歌名 | 歌手`，歌手可选但建议填写。

确认歌单为空时不会自动点歌。内置国歌、军歌、红歌相关关键词和部分常见歌名限制，禁播规则优先于确认歌单，手动点歌、本地文件、弹幕和 AI 都会经过检查。

规则依赖文字和元数据，不能识别所有改名、翻唱或音频实际内容，也不能替代你对播放内容和使用授权的核对。

### 7.4 循环背景 BGM

打开 **直播设置 → 背景 BGM**：

1. 勾选「循环播放背景音乐」。
2. 点击「选择背景音乐文件…」，选择本地音频。
3. 设置「背景音量」，例如 0.2；设置「说话 / 视频期间音量比例」，例如 0.25。
4. 保存后开始循环。

后一个比例是对背景音量再乘一次：0.2 × 0.25 = 0.05。数字越小，讲话时背景越轻。点歌播放时 BGM 自动暂歇，歌曲停止后恢复；直播暂停和断线时也会暂停。

### 7.5 奶蛙与透明互动视频

公开包不附带私人奶蛙素材，需要先准备自己的视频。

1. 打开 **直播设置 → 互动视频**，启用「奶蛙互动视频」。
2. 填写本地视频的绝对路径，例如 `D:\LiveMedia\奶蛙.webm`。文件需要在本机实际存在。
3. 设置触发词，例如「奶蛙,奶娃,小奶蛙」，再调整音量与显示大小。
4. 保存，使用「播放奶蛙视频」或测试弹幕检查。

建议使用带透明通道的 VP9 WebM，短片最多 8 秒、64 MB。文件扩展名是 WebM 并不代表一定含透明通道；没有透明通道的素材不能自动去掉背景。

EXE 包未附带 FFmpeg 可执行文件。可将自行合法安装的 FFmpeg 加入 PATH，然后重新启动程序；或在 PowerShell 为这次启动指定位置：

~~~powershell
$env:IMAGEIO_FFMPEG_EXE = 'D:\Tools\ffmpeg\bin\ffmpeg.exe'
.\Dy-Ai-Live.exe
~~~

上面的环境变量只对该窗口及其启动的进程有效，关闭后双击 EXE 不会继承它。需要长期使用时，在 Windows 用户环境变量中配置该项，再重新启动程序。

视频首次使用需要后台解码；之后复用缓存。重复触发可排队，但有容量上限，不是无限等待。直播暂停会冻结视频并暂停其声音，恢复后续播。素材未就绪时，大啤酒的随机回礼会保留热茶动作。

## 8. 人物、场景、换装和点赞整活

### 8.1 人物与换装

在 **直播设置 → 人物与互动** 选择「分层骨架（可抬手 / 换衣）」，并开启「自动响应弹幕 / 礼物动作」。工作台也可手动选择动作并点击「播放动作」。

- 普通动作：挥手、鞠躬、点头、跳舞、比心、倒立、转圈、变小、伸懒腰、探头、摆尾等。
- 「换衣服」「换装」「下一套」每次轮换服装；也可明确要求「穿雨衣」「穿水手服」「穿星空礼服」。
- 「换个配饰」独立轮换装饰；「戴墨镜」「戴皇冠」「戴蝴蝶结」指定配饰。
- 「恢复原装」恢复默认装扮。

服装与配饰独立，不需要先摘墨镜才能换衣。人物大小可调；水平和垂直位置设置主要用于经典舞台，三维场景中的位置请用场景命令调整。「显示骨架辅助线」用于调试，打开后会进入直播画面。

### 8.2 场景导演

在 **直播设置 → 三维场景** 开启原生三维场景，并允许「弹幕移动人物 / 转镜头 / 换天气」。可保存默认开播场景、天气和镜头。右侧「场景导演」里的临时操作用于当前场景，不等同于修改下次开播默认值。

| 玩法 | 观众可发送 | 结果 |
| --- | --- | --- |
| 轮换场景 | 切换场景 / 换个场景 | 在会客厅、云台、露台之间轮换 |
| 出门回家 | 出门 / 回家 | 去室外云台 / 回到海风会客厅 |
| 指定地点 | 去露台 / 去云台 / 去会客厅 | 切换到相应场景 |
| 环境漫游 | 散步 / 跑步 / 开车兜风 | 约 24 秒散步、15 秒跑步、18 秒驾驶演出 |
| 停车下车 | 停车 / 下车 | 停车仍坐在车内，下车走到车旁 |
| 家具互动 | 去沙发睡觉 / 去窗边看风景 / 喝茶 | 进入相应行为，窗边会调整观景镜头 |
| 结束休息 | 起床 / 醒醒 | 结束睡眠等场景活动 |
| 移动 | 往左游 / 往右游 / 向前游 / 回中央 | 按可行走区域移动 |
| 天气 | 下点雨 / 下点雪 / 恢复晴天 / 切换夜晚 | 改变天气，室内雨雪主要在窗外 |
| 视角 | 拉近镜头 / 拉远镜头 / 切换俯视 / 恢复全景 | 调整场景镜头 |

场景操作存在可配置间隔，连续刷指令可能被限制。人物会受场景边界和目的地约束，不是任意坐标移动。关闭三维场景后回到经典舞台，相关场景命令不再按三维玩法执行。

### 8.3 点赞达标整活

打开 **直播设置 → 点赞整活**：

1. 开启「点赞达标整活」，按需显示目标进度。
2. 设置「每增加多少赞触发一次」，默认 100。
3. 选择轮流、随机或固定动作，设置两段演出之间的休息时间。
4. 在工作台用「预览整活」直接看效果，或用「测试点赞 +10」检查计数。

当前包括约 16 秒流光环游、骑车、蛛丝摆荡和火箭表演。接入时会处理平台累计点赞的基线，不把接入前的大量历史点赞补播成整活；接入通道需正确提供新增数或总量。

高峰期整活有等待上限，最多等待 3 段；不是每个跨过的目标都会无限排队。修改阈值会从当前累计值重新建立目标；暂停会冻结动画与目标推进。同日重启保留今日点赞统计，但不会恢复所有未完成的动画队列。

## 9. 钓鱼玩法完整说明

### 9.1 两种模式

先在 **直播设置 → 钓鱼玩法** 启用「协力钓鱼」。

| 模式 | 如何进入 | 一局结束后 |
| --- | --- | --- |
| 普通单局 | 观众发送「钓鱼 / 去钓鱼」，或点击「场景导演 → 去钓鱼」 | 展示结果后返回原来的场景 |
| 常驻钓鱼直播 | 设置中开启「钓鱼专用直播（常驻界面，自动续竿）」，或工作台进入常驻钓台 | 留在钓台并自动开始下一竿 |

常驻开关会保存到运行配置，工作台按钮和授权弹幕的进出命令也会更新这个设置；下次启动按保存的选项进入。需要明确离开常驻模式时，使用「退出常驻钓台」或授权的「退出钓鱼界面」。

### 9.2 一竿的流程

1. 人物进入专用水域，在高台持竿垂钓，水中有不同体型的生物。
2. **等待咬钩**：每竿独立随机，默认 12～28 秒；普通拉钩需要等咬钩阶段。
3. **咬钩后溜鱼**：默认随机 25～45 秒的时限，开启语音时会提示观众帮忙。
4. 观众发送「拉」「拉钩」「提竿」增加收线进度；点赞和礼物也能贡献力度。
5. 收线进度达标会捕获，拉钩有概率脱钩，超时也可能失败；不是保证每竿成功。
6. 成功后展示鱼获图片、名称、价值和本轮贡献冠军，累计到今日价值榜，再按当前模式返回或续竿。

等待时间和溜鱼时限的最小值不能大于最大值，保存前检查范围。提前拉满会提前捕获，不会为了凑够时限继续等待。

### 9.3 谁获得鱼获

本轮贡献按以下方式比较：

~~~text
拉钩次数 + 可识别用户的点赞数 ÷ 每拉所需点赞数 + 礼物数量 × 每件礼物力度
~~~

- 默认 10 赞相当于拉一次，默认每件礼物相当于 5 次拉钩；都可修改。
- 抖音直连和浏览器协议采集按每条点赞消息的新增数量计入，不再因房间总赞数暂未变化而漏掉点赞；同一消息的网络重传仍会去重。
- 收线条旁显示百分比，少量点赞也能看见数值变化。等待咬钩时还没有可收的鱼，不增加收线进度；暂停或表演期间同样需要等钓鱼恢复。
- 贡献最高者获得本轮鱼获价值，同分时先参与者优先。因此不一定奖励第一个发「拉钩」的人，也不是固定“全部观众”。
- 只收到全场汇总点赞、缺少个人身份时，会计入匿名合力，不能据此编造获奖昵称。
- 为了稳定统计同名用户、榜单权限和获奖者，请确保弹幕助手提供稳定用户 ID。
- 咬钩时礼物强力拉钩，单次脱钩风险是普通拉钩的四分之一；常驻未咬钩时默认改为专属撒网，详见9.7。关闭撒网或普通单局时，未咬钩礼物仍预存助力。

默认普通拉钩脱钩概率为 0.06，即每次约 6%，不是整竿只有 6%。调整过高会明显增加失败，先用默认值体验，再按互动人数调整。

### 9.4 榜单、图鉴和趣味物品

- 今日钓鱼榜按用户累计鱼获价值排序；价值是玩法分数，不是现金或兑换承诺。
- 当前内容包含 44 种水族和 12 件趣味奇物，包括鲸鱼、鲨鱼、龙虾等，以及海水过滤器、鳗鱼过滤器等收藏物品。
- 趣味物品默认咬钩概率为 18%，可在设置中调整。
- 「今日出现」包含实际咬钩（含脱钩）与成功撒网捕获的对象，不计算背景游鱼；它与成功钓获数量不是同一个统计。
- 图鉴在水面底部紧凑轮播，排行榜、收藏记录同日重启保留。
- 过滤器等目前是可收藏、计分的趣味道具，不会真的给水域安装过滤设备。

### 9.5 谁能通过弹幕切换常驻界面

打开 **钓鱼玩法** 的「允许管理员 / 榜单前三切换常驻界面」，并选择权限依据：

- 钓鱼价值榜或礼物价值榜前三；
- 仅钓鱼价值榜前三；
- 仅礼物价值榜前三；
- 仅管理员。

管理员可来自接入源可信的管理员标记，或你填写的「额外管理员用户ID」。**填真实用户 ID，每行一个，不填昵称。** 自称管理员的弹幕、没有身份数据的消息，都不能据此取得权限；榜单依据为今日排名，排名变化后权限也随之变化。

授权观众发送「切换钓鱼界面 / 进入常驻钓鱼模式」进入，发送「退出钓鱼界面 / 退出常驻钓鱼 / 退出常驻钓鱼模式 / 关闭常驻钓鱼」退出。这里“切换钓鱼界面”表示进入，重复发送不会反向退出。普通「去钓鱼」是单局入口，“不钓了”不关闭常驻。主播也可在场景导演点击「退出常驻钓台」，或在设置关闭专用直播。

### 9.6 常驻时的其他互动与跳水

常驻钓鱼仍可换装、做动作、进行点赞整活或临时场景互动。不同玩法有不同处理：礼物完整演出会冻结钓鱼进度并在结束后恢复；临时场景互动结束后自动回钓台；换装保留新的外观。

发送「跳水」「花式跳水」「下水游泳」，或点击「花式跳水」，会播放约 24 秒的放竿、走到台边、跳水、水花、游圈和回台演出。跳水会惊走当前鱼并重新抛竿，不会带着原来的收线进度继续。

开启「下竿 / 咬钩 / 催拉 / 收获互动语音」可播报钓鱼状态，台词在「内置话术」里修改。正在播放其他发言时可能排队，不能把语音延迟误判为咬钩状态没有更新。

### 9.7 礼物撒网、松线和昼夜变化

**非咬钩礼物撒网**：常驻模式默认开启。人物放下鱼竿、挥臂撒网、沉网、收网，约10秒后展示至少8秒庆祝卡。AI语音会感谢和恭喜送礼者；1～5条鱼的图鉴分全部记给这个人，榜单和今日图鉴同步更新，随后继续原鱼竿。咬钩时仍使用原礼物动作和强力拉钩；撒网时本次普通礼物动作由撒网替代，墨镜外观仍保留。

在「钓鱼玩法」设置「每礼物价值单位对应图鉴分」，默认20。一网总分约为 **本次礼物总价值 × 倍率 × 随机0.8～1.4**。例如总价值100对应1600～2800图鉴分，不把数量再乘一次；这些是玩法积分，不可兑换。协议接入优先使用实际价格；缺少可靠价格时按数量估算，卡片明确提示。具体价格字段和排队规则见《钓鱼玩法与滚动公告》。

跳水或结果展示期间收到礼物先排队，同一用户待播礼物合并，最多32位排队；满队列则走原礼物动作与助力。撒网时不会被普通跳舞或跳水打断。暂停会冻结演出；明确退出常驻、关闭玩法或重启会取消未完成的撒网与队列，已完成鱼获保留。

| 新弹幕 | 实际效果 | 默认限制 |
| --- | --- | --- |
| 松 / 松线 / 放线 | 上鱼进度减少8个百分点，鱼线变松、人物摇头；不扣旧贡献、不奖励捣蛋者 | 咬钩时，全场间隔2秒；设置可关闭或调1～25个百分点 |
| 投饵 / 喂鱼 / 撒鱼饵 | 抛撒鱼饵，鱼群聚拢；动画后剩余等待缩短35%，最低3秒 | 等鱼时，全场间隔12秒 |
| 加油 / 护线 | 举手加油，接下来10秒基础脱钩风险减半 | 咬钩时，全场间隔10秒 |

这些动作也有场景导演按钮。内容相同的新弹幕可在冷却结束后再次触发；“不要松线”等否定句不会被本地口令当作松线执行。

**自动昼夜**：默认600秒完成一轮，白天到夜晚平滑变化，夜里显示星月、岸灯及倒影。在设置可选自动循环（120～7200秒）、跟随电脑当地时间、固定白天、固定夜晚。昼夜循环跨鱼竿持续，暂停冻结；AI上下文能看到昼夜、撒网送礼者、当前动作和加油剩余时间。

新增「钓鱼 · 礼物撒网」「钓鱼 · 撒网恭喜送礼者」话术，可编辑姓名、礼物、鱼种、数量和图鉴分占位符。以上全部使用原生Python/PySide6绘制，不需浏览器展示。

### 9.8 常驻自动互动和换钓点

常驻钓台不会一直保持同一个姿势：等待阶段没有礼物、点赞整活、语音或弹幕时，默认安静25秒后会随机做遮眼观察、伸懒腰、沿钓台挪位、检查鱼线等5～7秒动作。真实弹幕、礼物、关注和新增点赞会马上打断这段冷场动作。自动动作不拉钩、不造点赞、不制造观众或鱼获，也不会改变咬钩倒计时。

安静约90秒后，AI会结合当前钓点主动邀请观众发“投饵”“跳水”或“换个钓点”，邀请有冷却并能关闭。正在咬钩、礼物演出、语音、点赞整活或暂停时会让出控制权。

默认180秒没有成功收获，或连续3竿失败，系统会在等待咬钩的安全阶段自动换点；咬钩、收线、撒网、跳水和结果展示时不会切走。换点约10秒，人物提桶沿栈道移动，抵达后重新抛竿。三个钓点如下：

- **云汐钓台**：均衡鱼群。
- **芦苇浅湾**：小型水族概率提高。
- **星礁海岸**：鲨鱼、金枪鱼、龙虾、蝠鲼等海洋水族概率提高。

可以发送“换个钓点”“去芦苇浅湾”“去星礁海岸”“回云汐钓台”，也可以点击工作台按钮。设置中可分别关闭自动小动作、自动换点和冷场邀请，普通场景还可以设置无人互动多久后自动散步。

自动内容用于丰富节目节奏和减少画面长期静止，不能保证平台审核结果或避免封禁。

## 11. 画面布局、字幕、公告和费用

### 11.1 减少遮挡

在 **人物与互动** 可关闭聊天室、顶部统计图标、守护榜、字幕或气泡，也可缩小气泡。横屏和竖屏使用各自布局，先选方向，再决定哪些信息需要展示。

字幕设置目前位于 **钓鱼玩法** 页：调节「字幕字号」，并选择是否开启「字幕增加轻薄底色」。默认以轻量描边为主；内容较长会分页，不会把整段话全部铺在场景上。

「音乐播放器」在 **音乐与画面** 单独开关，「Token」在 **Token 用量与费用** 单独开关，「点赞目标」在 **点赞整活** 单独开关。关闭一种显示不会自动关闭对应功能。

顶部“在线”图标目前取自程序客户端连接计数，不能当成抖音平台实时在线人数；实际观众数应以平台为准。

### 11.2 滚动公告

打开 **直播设置 → 滚动公告**：

1. 开启「显示底部滚动公告」。
2. 填写「玩法介绍」，最多 2000 字；换行会合并为分隔内容。
3. 设置速度，范围 5～240 设计像素/秒。可先试 35，再按屏幕观感调整；这只是建议值。
4. 保存后立即生效。文本为空时隐藏。

可复制以下文案，并删除自己未开启的玩法：

~~~text
欢迎来到深蓝小屋！发“换衣服”切换造型，发“跳舞”“比心”看动作；发“出门”“回家”切换场景；发“下雪”“拉近镜头”改变环境；发“钓鱼”一起开竿，咬钩后发“拉钩”或点赞协力；发“跳水”看花式入水；点歌可说“播放 歌名”。想知道更多，发“你会什么”。
~~~

常驻钓鱼可使用：

~~~text
这里是深蓝钓台！等鱼发“投饵”；咬钩后发“拉”“拉钩”或点赞，“加油”护线，“松”会减少进度。非咬钩送礼可触发专属撒网，鱼获归送礼者！发“跳水”看花式入水，发“换衣服”切换装扮。管理员及授权榜单前三可发“退出常驻钓鱼模式”。
~~~

### 11.3 Token 与费用显示

在 **直播设置 → Token 用量与费用**：

- 开关「直播画面显示 Token / 估算费用」。
- 分别填写「输入价格」「输出价格」，单位均为 **元 / 百万 Token**，按你实际使用服务的计费信息填写。
- 费用按当前填写的价格估算；换价后会按新单价重算当前累计用量，不是按历史价分段记账。

计算方式为：

~~~text
估算费用 = 输入 Token ÷ 1,000,000 × 输入单价
         + 输出 Token ÷ 1,000,000 × 输出单价
~~~

示例：输入 10,000 Token、输出 2,000 Token，若设置输入 1 元/百万、输出 2 元/百万，则估费 0.014 元。此处价格仅演示公式，不代表任何服务商报价。

用量包含意图识别和模型回复等调用；接口未返回完整用量时会估算并标记。今日统计同日重启恢复，按电脑本地日期切换到新一天；服务商账单才是实际结算依据。隐藏显示不会停止 AI 调用或费用累积。

## 13. 每次使用、备份和升级

### 13.1 开始前检查

1. 启动程序，确认「今日数据自动保存」没有报错。
2. 确认弹幕源、房间号、接入开关正确，正式使用前退出模拟模式。
3. 用真实观众消息测试一次，确保昵称、用户 ID、礼物名称和点赞能够传入。
4. 检查 AI、语音、BGM、互动视频的可用性和音量。
5. 确定横竖屏、默认场景或常驻钓台、公告内容以及常驻模式管理员名单。
6. 在 OBS 检查画面和声音，先录制一小段回看。
7. 确认自己的使用方式在许可范围内，再按平台流程开始直播。

临时休息使用「暂停直播」，继续时恢复。结束时先处理 OBS/平台推流，再正常退出程序，等待进程结束后备份数据。

### 13.2 文件保存在哪里

默认运行目录：EXE 版为 EXE 所在文件夹，源码版为项目根目录。如果设置了 `DEEPY_HOME`，以下运行文件改存到该指定目录；资源仍从安装包读取。

| 文件/目录 | 用途 | 升级时怎么处理 |
| --- | --- | --- |
| `.env` | 环境配置，可能含模型密钥或 Cookie | 私下备份，勿公开 |
| `data/runtime.json` | 界面保存的运行配置、人设、话术等，也可能含密钥 | 保留；不必手工编辑 |
| `data/live-stats.sqlite3` | 按日保存的 Token、回应、事件计数、礼物/钓鱼排行和点赞进度等 | 退出程序后备份 |
| `data/` 其他内容 | 运行缓存、浏览器状态或自行存放的素材等 | 需要迁移时一并私下备份 |
| `music/` | 本地曲库 | 保留，或重新配置外部曲库目录 |
| `logs/` | 启动、运行和错误日志 | 排查用；公开前脱敏 |
| `_internal/` | EXE 依赖与只读资源 | 使用新包附带版本，不用旧目录覆盖 |
| 自选 BGM / 视频文件 | 可能位于程序目录之外 | 单独保留，换电脑后更新设置中的路径 |

同一天重启会加载当天记录；跨天按**电脑本地日期**使用新一天统计。因此请保持系统日期正确，不要用修改系统时间的方法清零。图鉴的“今日出现”和排行榜会按各自规则恢复。

持久统计不代表全部运行过程都能续上：当前语音、未播完的歌曲、动画队列和半竿钓鱼不保证在退出后恢复。突然断电也可能丢失最后一次落盘之后的少量数据，尽量正常退出。

### 13.3 升级 EXE

1. 正常退出旧程序。
2. 复制备份旧目录中的 .env、data、music 及外部媒体；不要只备份 EXE。
3. 将新版本完整解压到一个新目录，保留它自己的 _internal。
4. 将需要的旧 .env、data、music 复制到新运行目录，外部媒体路径不变时可继续使用。
5. 启动新版本，检查设置、当天统计、BGM、视频和 OBS 输出，再决定何时移走旧目录。

不要运行旧版和新版同时写入同一份 data，也不要把 data 上传到公开仓库。迁移前保留完整备份，避免错误配置或版本差异影响唯一一份数据。

### 13.4 用独立数据目录进行演示

如果希望演示与自己的真实统计、密钥完全分开，可在**没有其他实例运行时**为演示指定一个新的空目录：

~~~powershell
$env:DEEPY_HOME = 'D:\DyAiLive-DemoData'
$env:LLM_BASE_URL = ''
$env:LLM_MODEL = ''
$env:LLM_API_KEY = ''
$env:TTS_ENGINE = 'none'
.\Dy-Ai-Live.exe --demo
~~~

先确认指定的是新的空目录，里面没有以前的 .env 或 runtime.json。这个窗口中的环境变量只用于该次测试；关闭窗口后恢复正常启动。不同运行目录能隔离数据，但默认端口相同，因此不能靠它同时启动多套默认服务。

## 14. 常见问题与排查

### 14.1 双击 EXE 或 BAT 后闪退

- EXE：重新确认完整解压、_internal 在旁边、目录可写；查看 `logs/launcher.log` 和启动错误提示。
- 源码：在项目根目录 PowerShell 用虚拟环境的明确 Python 路径启动，让错误留在终端；不要只反复双击 BAT。
- 如果提示缺少 PySide6、imageio_ffmpeg 等模块，说明当前启动的 Python 没装桌面依赖，使用**同一个 Python**安装 requirements-desktop.txt。
- 检查是否已有旧实例占用端口，先正常退出自己的旧工作台，再重试。

源码排查示例：

~~~powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -X utf8 -m pip install -r requirements-desktop.txt
.\.venv\Scripts\python.exe -X utf8 -m app --desktop
~~~

依赖安装失败时保留完整报错；不要反复修改项目文件来修复网络下载问题。

### 14.2 工作台一直显示连接中，或 OBS 无画面

1. 查看 logs 中后台是否已成功启动，确认没有端口占用错误。
2. 若工作台有画面但 OBS 没有，重新复制「画面输出」中的实际地址，检查媒体源关闭了本地文件选项。
3. 确认地址是视频的 18849 端口，不是主服务 8848 或弹幕桥接 5001。
4. 若 OBS 在另一台电脑，127.0.0.1 指向的是 OBS 自己；本教程默认同一台电脑运行，不包含跨机器开放服务配置。
5. 横竖屏切换后重新适配来源尺寸，必要时重新加载媒体源。

只读检查本机端口是否可连接：

~~~powershell
Test-NetConnection -ComputerName 127.0.0.1 -Port 8848
Test-NetConnection -ComputerName 127.0.0.1 -Port 18849
~~~

端口连通只代表那里有服务，不能证明一定是正确版本的本程序。

### 14.3 有字幕但没声音，或声音有重音

依次检查：语音引擎是否为「仅显示字幕」、全局是否静音、Windows 应用音量、输出设备、Edge 语音网络访问、日志中的 TTS 错误。

本地能听见而 OBS 没声时，检查 OBS 音频采集源；视频地址本身不携带音频。重音时检查同一声音是否被桌面采集和应用采集重复添加。

语音中途结束时检查是否点击跳过、开始新人工播报、试听话术或暂停。字幕会分页，先区分“字幕换页”与“声音真的被截断”；再检查原始话术每行是否完整以及网络合成是否失败。

### 14.4 真实弹幕没有进来

先在工作台发送测试弹幕：本地测试有效说明互动管线基本可用，问题更可能在外部采集。

- 桥接：检查助手是否主动连接 5001，消息是否为支持的 JSON 字段，是否实际进入目标直播间。
- HTTP：确认额外桥接进程运行在 5002，主程序也已启动。
- 浏览器采集：检查房间正在直播、采集浏览器没有关闭、必要验证已完成。
- 直连：检查 Node.js 和签名组件；公开包不附带 SDK，缺失时请改用桥接。
- 确认没有忘记勾选「启用弹幕接入」，也没有仍处于模拟源或暂停状态。

### 14.5 AI 不回复，或者只会固定指令

检查模型接口地址、名称、密钥是否来自同一个服务配置；查看日志中的鉴权、超时、模型不存在或请求格式错误。先用简单聊天确认模型可用，再测试复杂意图。回退到本地规则时，明确命令仍可能成功，不能据此证明在线 AI 已连通。

同一段操作有时会用到意图识别和回复两类调用。不要把“有动作但没有即兴聊天”直接判定为整条互动完全失败。

### 14.6 点歌失败或 AI 不自动选歌

检查音乐启用、队列容量和歌曲限制。AI 自动选歌还需要非空的已确认歌单。在线音频不可用时用本地曲库测试；歌曲被规则拒绝时按提示换歌，不建议为测试而移除全部内容限制。

BGM 没响时检查本地路径是否还存在、是否正在点歌播放、是否静音或暂停；BGM 在歌曲期间暂歇是正常行为。

### 14.7 奶蛙不出现、黑底或没有声音

检查视频开关、有效路径、8 秒/64 MB 上限、FFmpeg 路径和日志。黑色矩形通常需要核对素材是否真的有透明通道；有画面无声音还需检查原文件是否含音轨、视频音量和 OBS 音频源。首次解码稍有等待不等于按键无效。

### 14.8 钓鱼命令失败，奖励名字不对

- 确认「启用协力钓鱼」和「自动响应弹幕 / 礼物动作」均开启。
- 等待咬钩阶段不能按已咬钩方式拉鱼；观察状态再参与。
- 切换常驻需要接入源管理员标记或用户 ID 对应的今日前三，昵称相同不代表身份匹配。
- 奖励归贡献最高者，缺少实名点赞不能推算某个人是点赞最多者。
- 礼物演出时钓鱼暂停推进，演出结束后再观察；跳水则会惊走当前鱼重新开竿。
- 常驻模式收竿后仍可能续竿，明确离开请使用「退出常驻钓台 / 退出钓鱼界面」。

### 14.9 重启后数据不见了

先确认是否同一天、是否启动了另一份目录、是否更改 DEEPY_HOME，以及 data/live-stats.sqlite3 是否还在。观察工作台的保存状态；复制源码或换 EXE 文件夹不会自动迁移旧目录的数据。

如果提示数据读取损坏，先退出并备份原文件，不要立即删除数据库或清空 data。提交问题时提供错误日志和版本信息，不公开整份个人数据库。

### 14.10 中文乱码或字体缺字

本项目源码、文档、配置和日志使用 UTF-8。使用支持 UTF-8 的编辑器保存自定义文件，别把中文配置保存为 ANSI/GBK；源码命令可加 `-X utf8`，或设置 PYTHONUTF8=1。

乱码（字符变成错误文字）与缺字方框（字体不含该字）不同。前者检查编码，后者检查 Windows 中文字体。不要为了排查显示问题批量转码整个项目或覆盖自己的配置。

### 14.11 怎样反馈问题

在仓库 Issues 提供：使用版本或 build-info.json 中的提交号、EXE/源码启动方式、弹幕来源、复现步骤、期望结果、实际结果，以及脱敏后的相关日志。截图尽量包含状态提示；说明是工作台无声、OBS 无声还是两者都无声。

不要上传 API 密钥、Cookie、完整 .env、runtime.json、直播用户数据库或私人素材。缺少这些文件不妨碍先用错误堆栈、接口状态码和最小复现步骤排查。

## 15. 当前功能边界

- 场景包含三维几何与透视表现，人物本体是二维分层鱼尾骨架，不是完整的三维人形模型；换装只覆盖已经制作的服装和配饰。
- 原生版不直接加载任意 Cubism / .moc3 模型。公开源码中的 web/assets/whale/art 是原生画面也会用到的素材，不能因为叫 web 就整目录删除；EXE 用户保留完整 _internal 即可。
- AI 读取本项目的运行状态并调用允许的功能，不会随意操控电脑，也没有通用桌面截图识别或外部游戏画面理解功能。
- 自动构建验证程序启动和原生渲染，不代表替你验证了真实直播间、付费模型、在线语音或私人视频。正式使用前仍需检查自己的接入环境。
- 原生后台持续绘制可以避开网页后台节流，但不承诺所有机器、网络和推流设置下永不卡顿。

更多专题说明见仓库 [文档导航](https://github.com/bucai2417/Dy-Ai-Live/blob/main/docs/README.md)，自行打包见 [Windows 自动构建说明](https://github.com/bucai2417/Dy-Ai-Live/blob/main/docs/Windows自动构建.md)。EXE 包中的 THIRD_PARTY_NOTICES.md、THIRD_PARTY_LICENSES 和 Windows自动构建.md 提供第三方许可及相应源码信息。
