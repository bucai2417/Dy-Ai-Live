# 语音完整播报、话术编辑与冷场互动

## 本次修正的原因

检查发现，之前部分内容在送给语音合成前就已经不完整：冷场模型回复超过 18 字就停止接收，欢迎和感谢超过目标字数时会直接截字，普通回复也可能在逗号处提前结束。播放器端还有两个问题：待播队列最多 12 段，超过后自动挤掉旧段；单段播放超过 35 秒会被当成超时，即使播放进度仍在前进。

现在内置话术完整传给分句合成，不受模型回复目标字数截断。模型回复达到目标后会等待句末标点再收尾，不再在逗号处直接截断。生成持续过长或超过等待时间时只采用已完成的句子；没有完整句则跳过此次生成并记录日志。模型中途失败转入离线话术时，使用完整的兜底话术，避免把半句模型内容拼接到模板前面。

原生工作台连接后登记为语音播放器。服务端每推送一段音频，等待播放器完成确认后再处理下一段；语音忙碌状态保持到实际播放结束，冷场任务因此不会误认为已经说完。普通消息和礼物感谢排队播报；人工播报、跳过、直播暂停和断线仍可主动中止。旧版或未登记播放器保持兼容推送；多个原生工作台同时连接时，以最先登记且仍在线的工作台确认播放进度。

原生待播队列取消 12 段自动挤出限制，正常服务端使用逐段完成确认控制发送速度。播放器仅在连续 30 秒播放位置没有变化时报告卡住，正常前进的长音频继续播放。合成失败仍保留字幕；播放错误、断线、取消和确认超时会释放等待，避免调度永久卡住。

## 修改内置话术

重启工作台与后台服务一次后，打开「直播设置 → 内置话术」。

- 分类包含进场 / 多人 / 批量欢迎、普通与大额礼物感谢、关注 / 点赞感谢、动作 / 换装回应、冷场话题与邀请、自动点歌开场，以及 11 类离线聊天回复。
- 原有互动规则的回复也列入分类，编辑时保留规则的触发条件、动作和冷却设置。
- 普通类别每行一条候选话术。下方显示光标所在行的中文示例和允许的占位符，例如 {name}、{gift}；非法占位符会禁止预览播报，保存时也会校验。
- 「恢复本类默认」只恢复正在编辑的类别，点击「保存并生效」后才写入配置。普通类别留空使用默认话术；规则台词留空表示只做视觉互动。需停止某类自动播报时使用对应开关。
- 「播报光标所在话术」使用当前生效音色和语速，走正常人工播报流程，会停止当前播报并送到工作台音频输出；直播软件可以采集到它。修改话术文字无需先保存即可检查该行，但修改音色 / 语速需先保存。
- 「语音与节奏」增加礼物、关注、优先 AI、离线回复与离线朗读开关，以及模型回复目标字数。开启「优先使用 AI 即兴台词」时，部分欢迎、感谢和冷场内容由模型生成；关闭后使用编辑的预设台词。

话术最多每类 100 条、每条 2000 字。中文配置按 UTF-8 原子保存。系统报错、歌曲查询结果等动态操作提示继续由对应功能生成，不属于可编辑的表演话术。

## 新增互动与冷场动作

| 弹幕示例 | 人物效果 |
| --- | --- |
| 比个心、送我一颗爱心 | 脸红、轻轻摇摆和爱心粒子 |
| 伸个懒腰 | 人物舒展、眯眼和星光 |
| 探个头 | 左右探头、倾斜和气泡 |
| 飘起来、水母漂浮 | 上下漂浮、轻轻摆动 |
| 打个盹、打瞌睡 | 闭眼、缓慢点头 |

这些效果使用现有立绘变换和原生粒子，不是新增骨骼模型或真实手指比心。可从工作台人物动作列表直接预览，也可以通过本地明确指令或已配置的 AI 意图识别触发；重复弹幕仍按现有规则处理，否定请求不会被当作明确动作指令。

「直播设置 → 冷场互动」可独立开启自动动作，默认安静 25 秒后表演，支持勾选候选动作、依次轮换或随机不连续重复。每次收到观众事件重新计时；播报、待回复消息、待欢迎观众、点赞整活或直播暂停时不自动插入。正在播放互动视频或更高优先级的人物动作时，画面端也会避让。

冷场聊天继续使用「语音与节奏 → 冷场等待」间隔，默认配置为 45 秒；有旧配置时沿用原值。使用预设话术时，轮换「冷场话题」和「冷场互动邀请」，逐条使用候选内容。生成话题期间有新观众互动到来，会放弃过时的冷场发言。音乐播放期间默认允许无声动作、暂缓冷场聊天，可在设置开启音乐期间聊天。

冷场互动现增加“主动邀请观众体验已开启的玩法”，默认最短间隔 180 秒。第一次满足冷场条件时优先邀请钓鱼，随后轮换场景、换装、整活和点歌；关闭的玩法自动跳过。在线 AI 即兴邀请，离线使用“内置话术 → 玩法邀请”中的完整台词，邀请本身不触发玩法。钓鱼、人物行为和高优先级动作进行中不会插入冷场发言。关闭玩法邀请后继续原来的话题轮换。

预览按钮使用已经保存的冷场动作选择。关闭自动动作不影响手动预览；暂停直播时手动预览也不执行。冷场聊天与动作互相独立，分别关闭即可安静等待观众。自动点歌仍遵循已有确认歌单与禁播规则。

## 验证范围

2026-11-07 全套 406 项测试通过，保留 3 条已有依赖弃用提示；Python 编译检查通过。正式配置与修改前备份逐字节核对，测试使用独立配置，未改动实际密钥或直播接入参数。

tests/test_speech_idle.py 覆盖流式半句、完整模板、播放完成确认、取消 / 断线 / 播放失败、超过 12 段的队列、正常长音频、中文编辑保存、非法占位符、动作触发、冷场间隔、音乐避让与新弹幕到达。

tools/check_native.py 使用隔离配置和本地测试音频验证三段真实 QMediaPlayer 播放及完成确认，并保存话术编辑、冷场设置和五种动作的横竖屏截图。本机最新测量：横屏最小化 4 秒输出 121 帧，竖屏 120 帧，均约 30 FPS；视频流维持 25 FPS。短时测量不替代长时间实际推流。

本轮没有调用真实在线模型或在线 Edge TTS，也未连接真实抖音房间。已确认的是本地文本、排队、播放与互动链路；上游服务返回缺失音频、网络故障或音频设备异常仍可能造成无法播出，工作台会保留字幕并显示播放错误。
